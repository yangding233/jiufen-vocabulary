# 离线语音维护

本页供维护者重新生成和核对音频。普通使用者只需安装配套版本，在词卡选择英式／美式和正常／慢速；不需要安装下面的开发环境。

音频在开发电脑提前生成，安装包只带 AAC-LC／M4A 成品。生成脚本读取内置词条和发音映射，不打开学习数据库，也不读取个人联想或笔记。

## 1. 准备独立开发环境

以下命令在项目根目录的 PowerShell 中执行。需要 Python 3.12、`uv` 和可用的 FFmpeg；FFmpeg 只用于开发转码。

```powershell
$taskRoot = (Get-Location).Path
$env:UV_CACHE_DIR = Join-Path $taskRoot 'build\uv-cache'
uv venv .venv-audio --python 3.12
uv pip install --python .venv-audio/Scripts/python.exe -r tools/audio-requirements-lock.txt
```

`tools/audio-requirements-lock.txt` 锁定本轮使用的 99 个开发依赖。`.venv-audio`、下载模型和生成候选均在忽略目录中，不加入源码发行包。

英语音素转换还需要单独安装官方 spaCy 模型 `en_core_web_sm 3.8.0`。先下载 wheel、核对 SHA256，再安装：

```powershell
New-Item -ItemType Directory -Force -Path build/vendor | Out-Null
$taskSpacyWheel = Join-Path $taskRoot 'build\vendor\en_core_web_sm-3.8.0-py3-none-any.whl'
Invoke-WebRequest -Uri 'https://github.com/explosion/spacy-models/releases/download/en_core_web_sm-3.8.0/en_core_web_sm-3.8.0-py3-none-any.whl' -OutFile $taskSpacyWheel
$taskSpacyHash = (Get-FileHash -LiteralPath $taskSpacyWheel -Algorithm SHA256).Hash.ToLowerInvariant()
if ($taskSpacyHash -ne '1932429db727d4bff3deed6b34cfc05df17794f4a52eeb26cf8928f7c1a0fb85') { throw 'spaCy wheel 校验和不匹配，停止安装。' }
uv pip install --python .venv-audio/Scripts/python.exe $taskSpacyWheel
```

生成器会先检查该模型已经安装，不会在生成过程中偷偷下载它。生成期启用 Hugging Face／Transformers 离线模式。Misaki 显式使用本地 `EspeakFallback` 处理字母到音素的转换；最终声音仍由 Kokoro 模型生成。

## 2. 下载并核对语音模型

```powershell
.\.venv-audio\Scripts\python.exe tools/download_audio_model.py
```

脚本只从 `thewh1teagle/kokoro-onnx` 的 `model-files-v1.1` 官方发布附件下载，保存到 `build/vendor/kokoro`，并核对固定体积和 SHA256：

| 文件 | SHA256 |
| --- | --- |
| `kokoro-v1.0.onnx` | `beb0d1848dee9a49da392cc3df26958d46cfa35d321edf434f52949153f0df3a` |
| `voices-v1.0.bin` | `bca610b8308e8d99f32e6fe4197e7ec01679264efed0cac9140fe9c29f1fbf7d` |

已存在且通过校验的文件会复用。未完成的 `.download` 文件会保留并使脚本停止，避免把半个模型当作完整模型使用。

本轮音色为美式女声 `af_heart`、英式女声 `bf_emma`。模型、工具及上游训练来源的归属说明见 [第三方说明](../THIRD_PARTY_NOTICES.txt) 和 [数据来源与许可](数据来源与许可.md)。

## 3. 先生成和试听样本

```powershell
.\.venv-audio\Scripts\python.exe tools/build_neural_audio.py --encoder 'D:\工具\ffmpeg.exe'
```

请把 `--encoder` 改为本机实际的 FFmpeg 完整路径。开发工作区也可使用脚本默认的 `../work/video-bin/ffmpeg.exe`。

默认生成 20 个词库样本，以及额外的 `transparent` 试听。`transparent` 不在这份 1,493 词常规词库中，只进入试听区，不计入词库覆盖和正式音频数量。

完成后打开 `build/neural-audio/试听.html`，每种口音都可比较旧版、神经语音正常版和慢速版。试听页和候选音频均可断网打开；此步骤不替换 `web/audio` 中的正式资源。

检查内容包括：

- 单词和短语是否完整，有没有额外念出文字、漏读、爆音或很长的空白。
- `audience`／`audiences` 等单复数形式的词尾，以及长词的重音。
- 英美两种口音是否分别符合目标，慢速是否保持音调。
- 多读法词是否按词条释义对应的顺序朗读，播放提示是否说明读法。

`tools/audio-pronunciation-overrides.json` 记录需要显式指定的读法、词性和核查来源。正常读音来自 Kokoro；慢速文件经 FFmpeg `atempo=0.75` 生成，再以正常播放速率播放，避免同时减速两次。

## 4. 生成全词库候选

```powershell
.\.venv-audio\Scripts\python.exe tools/build_neural_audio.py --all --encoder 'D:\工具\ffmpeg.exe'
```

全词库为 1,493 个词条，每词两种口音、正常和慢速各一份，共 5,972 个正式 M4A 文件。候选保存在 `build/neural-audio/audio`；清单保存在 `build/neural-audio/audio-manifest.json`。

脚本按词条、口音、音素、配方、模型和开发依赖生成指纹。重复运行时，指纹和文件哈希均一致的候选会复用；中断后可以重跑同一条命令继续。候选生成完毕仍不自动替换正式资源。

## 5. 安装候选并刷新网页资源

试听和候选检查通过后，再执行独立安装步骤：

```powershell
.\.venv-audio\Scripts\python.exe tools/build_neural_audio.py --install
python tools/build_audio.py --check
python tools/upgrade_web.py
node tools/build_content.cjs
python apps/ios/verify-resources.py
```

`--install` 要求完整的 1,493 词候选清单，检查预期文件集合、路径、时长、格式和 SHA256。正式替换前会备份旧 `audio` 目录与旧清单到 `build/audio-before-kokoro`，再进行同磁盘目录切换；安装检查失败时恢复旧音频和清单。

同一候选集只安装一次。旧备份目录已经存在时，安装器会停止，保留旧快照。维护下一个版本时先另存并核对既有快照，或在新的工作区构建，避免覆盖唯一的旧版备份。

`build_audio.py --check` 只核对文件，不需要合成器或模型。旧 eSpeak 生成命令不能复用 Kokoro 清单来覆盖新音频；本版重新生成应使用 `build_neural_audio.py`。

## 6. 自动检查与辅助转写

```powershell
python tests/audio_manifest_test.py
python tests/neural_audio_test.py
```

这两套检查合计 18 项，覆盖清单与路径校验、正常／慢速结构、词典 IPA 到模型音素的重音转换、发音目标和安装回滚等逻辑，不运行语音模型，也不接触用户档案。它们不能证明每个单词听起来都自然。

样本还可以使用本地 `faster-whisper-small` 做辅助转写：

```powershell
.\.venv-audio\Scripts\python.exe tools/check_neural_samples.py --model 'D:\模型\faster-whisper-small'
```

`--model` 必须指向已经下载的本地模型目录；检查脚本不自动下载模型。转写前先用 FFmpeg 转成 16 kHz PCM，避免依赖 PyAV 直接解码时的兼容问题。

转写结果用于发现可能的漏读或额外内容，不能替代对音素、重音、词尾和口音的核对，也不能记成“真人逐词审听通过”。音频结构、辅助转写、人的试听和实际手机验收，应在 [验收清单](验收清单.md) 分别记录。

## 7. 打包后的检查

Windows 和 iPhone 都要从新安装包取得音频；内容包和 USB 学习进度同步不会替换安装包中的声音。生成工具、模型、PCM 候选和试听页保留在开发区，运行包只带正式 M4A 与清单。

发布前核对打包后的正常／慢速选择、英美切换、退出播放、保存重开，以及最终 IPA 的版本、资源哈希和 Xcode 构建结果。实际 iPhone 的飞行模式冷启动、静音模式、锁屏停止和覆盖升级保留进度，以真机结果为准。
